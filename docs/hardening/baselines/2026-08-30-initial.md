## Correctness validation

- `npm run typecheck`: **pass** for web and site-content workspaces.
- Seed build during test preflight: **pass**, producing a 9,734-byte seed and
  43-byte AOT example.
- Core output observed before the long application workers: **pass**, including
  current compiler-subset equivalence, unsupported-compiler rejection,
  reproducible seed byte identity, pin drift rejection, independent sessions,
  lexical/macro/application examples, resource-cap failures, byte bounds and
  atomic block operations, tail-call depth, explicit heap reserve/release, and
  raw byte handoff.
- Full inherited `npm test`: **263 pass, 21 fail, 284 total**, with no skips or
  cancellations, in 5,519.638 seconds on the loaded audit host. The duration is
  traceability only and is rejected as a performance baseline.

The 21 failures were:

- six long actor-route assertions (records 148, 215, 294, 348, 366, and 383)
  plus the 401-row actor-hash gate;
- three long application movement/frame/allocation gates;
- five projected door/route gates plus the long door-use gate;
- the live cross-checkout mirror and a second assigned-mirror assertion;
- the reused-static-slot, repeated status-render, and palette assertions.

All seven retained actor/actor-hash diagnostics were `heap exhausted`. The
other long application/replay failures cluster at the same resource boundary,
but their diagnostics were not all retained in the truncated aggregate output,
so this baseline does not promote that inference to a confirmed cause. The
mirror failures were independently reproduced as dependence on a newer, dirty
external checkout rather than on the pinned local payload. Static, status, and
palette failures remain distinct until individually localized.

No general interpreter/compiler/bootstrap differential runner exists. The
current compiler-equivalence test covers three arithmetic expression shapes at
six inputs. Therefore “no earliest divergence” is not yet a valid whole-language
claim. The earliest evidence gap is the missing M1 runner itself.

## Memory evidence

- Seed memory starts at 16 WebAssembly pages and has a 4,096-page type maximum.
- Growth is explicit through `heap.reserve`.
- The allocator is a bump pointer; there is no collector.
- A regression test shows a minimal state tick allocates nonzero but less than
  512 bytes/tick.
- `heap.release` can bound a manually managed arena region.

This fails the intended high-level acceptance criterion: ordinary long-lived
programs still need a manual region discipline or eventually exhaust their
declared cap. Live/retained object counts, fragmentation, GC throughput, pause
percentiles, leak slope, and collector soak stability are unavailable because
no collector exists.

## Performance evidence disposition

The repository's existing tests reported precompiled cold/setup diagnostics and
the feasibility script can measure fixed-point stepping, byte handoff, state
transport, and allocation burn. Those are useful smoke measurements, but they
do not implement fixed warmups, raw repeated samples, percentiles, variance
gates, affinity, or quiet-host rejection. No performance number from this
initial loaded-host audit is promoted as a baseline.

## First prioritized gap

Implement M1: one declarative golden observation corpus and deterministic stage
runner that records values, ordered effects, errors, named state probes/hashes,
and the earliest divergence. This is smaller and more valuable than expanding
the compiler or changing the allocator before semantic comparison exists.
