Interfaces / 02

System interface

Portable system
services.

The System Interface is the small, capability-based boundary between a YALisp program and the environment that runs it. It describes effects, not a particular operating system.

Programs receive only the capabilities a host explicitly provides. A document evaluator can expose storage and clocks without exposing the network; a server can expose sockets without exposing a window.

01 / Model

Values stay portable.
Effects cross the boundary.

Core evaluation, data, errors, and Assembly forms have no ambient system access. A system operation is an explicit call on a named interface, returns ordinary YALisp values, and can fail only through its documented result.

capability

Granted, never discovered

A host hands a program a value representing a permitted service. There is no hidden global filesystem, clock, process, or network.

resource

Owned and closed

Streams, directories, sockets, and timers are opaque resources. The caller closes them; the host releases them when their scope ends.

result

Data, not host exceptions

Operations return a value or a structured condition with a stable kind, message, and contextual fields. Host exceptions do not become language semantics.

02 / Portable interfaces

One vocabulary,
many runtimes.

The initial surface follows the WebAssembly Component Model’s useful distinction: world-facing interfaces are named, typed contracts. YALisp keeps the naming and capability discipline while presenting natural Lisp data.

system.environment

environment.get · arguments · working-directory · temporary-directory

Read process context supplied by the host. Environment access is opt-in because it may carry secrets.

system.clocks

wall.now · monotonic.now · sleep · timer.open · timer.close

Separate civil time from monotonic duration. Tests can supply a deterministic clock capability.

system.files

file.open · read · write · seek · flush · stat · directory.list · create-directory · remove · rename · close

Paths are host-defined handles, not promises of a POSIX filesystem. Sandboxed and browser hosts can implement the same contract.

system.streams

stdin · stdout · stderr · stream.read · stream.write · stream.flush · stream.close

Byte streams provide the base for text readers, REPLs, logging, pipes, and file handles.

system.network

resolve · tcp.connect · tcp.listen · udp.bind · socket.read · socket.write · socket.close

Networking is a distinct capability. DNS and sockets are never implicitly available to a program.

system.random

random.bytes · random.u64

Cryptographic randomness comes from the host. Deterministic program randomness belongs in a passed seed or pure library, not this interface.

03 / Contract rules

Portable means
precise at the edges.

01

Bytes first

Files and streams exchange byte vectors. Text encoding is selected by a higher-level reader, making UTF-8 policy explicit instead of platform accidental.

02

Async without ambient promises

An operation may suspend, but its YALisp result is still a value or condition. Hosts decide how a pending operation is scheduled and surfaced to the event loop.

03

Stable error kinds

Conditions use portable kinds such as not-found, permission-denied, already-exists, invalid-input, closed, and io. Platform codes remain optional diagnostic data.

04

No platform leakage

POSIX descriptors, browser exceptions, Node buffers, and WebAssembly handles are host implementation details. They may not appear in portable program contracts.

04 / Profiles

The same program,
different grants.

document

Editor and sandbox

Memory-backed files, clocks, UI events, and an optional project store. No process or unrestricted network access.

command

CLI and build tool

Arguments, standard streams, scoped filesystem roots, clocks, and explicitly requested network access.

service

Long-running runtime

Configuration, structured logs, network listeners, durable storage, timers, and supervised lifecycle hooks.

This is the normative YALisp System Interface contract. A profile is a documented bundle of capabilities, not a second language. Libraries declare the interfaces they need, so a host can reject an incompatible program before it performs an effect.
