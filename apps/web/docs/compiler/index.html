Compiler

One expression.
Three real paths.

YALISP now has a deliberately bounded Lisp-written compiler milestone. The interpreter evaluates compiler.lisp, which lowers a verified arithmetic subset to WebAssembly text; the Playground can assemble that output just in time or load the artifact produced ahead of time during the site build.

01

Interpreted · seed

The WAT seed parses, evaluates, and prints every call to the benchmark function.

02

JIT · browser

The checked-in Lisp compiler emits a function payload, then the browser assembles, compiles, instantiates, and runs a fresh WebAssembly module.

03

AOT · build

The production build runs that same compiler on the same workload and checks in the resulting aot-benchmark.wasm artifact for later browser instantiation.

Run the measured comparison in the Playground. It reports interpreter preparation/run time, JIT compilation preparation separately from run time, and AOT browser preparation separately from run time. Every displayed number is measured after the visitor taps Run.

01 / Supported subset

Small enough
to prove.

shape

One parameter, one expression

The compiler accepts exactly one distinct parameter and one body form.

expressions

Integer arithmetic

Integer literals, the parameter, and nested binary +, -, and * forms are supported.

boundary

Reject, never pretend

Calls, conditionals, division, extra parameters, multiple forms, and unknown names return nil and remain interpreter-only.

Equivalence is guaranteed only while inputs and intermediate results stay in the seed's signed 30-bit fixnum range. This milestone is not a general YALISP compiler, module system, or self-hosting compiler.
