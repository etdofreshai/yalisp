Interfaces / 03

DOM

Documents and events,
on every target.

The DOM Interface is the single portable document-and-event contract that YALisp applications target. It covers documents, retained nodes, rendering surfaces, input, commands, and accessibility without making the browser’s object model part of the language.

The planned browser binding forwards this contract directly to the native browser DOM. The planned SDL and bare-metal binding forwards the same calls to YALisp’s lightweight in-memory document tree and SDL-backed renderer. These are adapter contracts; no DOM runtime binding is implemented in this repository yet.

01 / Boundary

Applications target.
Adapters forward.

Application code sees one DOM contract rather than branching between browser nodes and SDL resources. A binding forwards document mutations, event subscriptions, commands, and presentation work to the target adapter, which owns layout, scheduling, focus, and native integration.

document

Persistent editable state

Named text, structured data, selections, and versioned edits. An adapter may back them with a browser workspace, filesystem capability, database, or collaborative session.

tree

Retained portable structure

Stable keyed nodes carry content, layout intent, controls, and semantic metadata. Browser bindings map them to native nodes; SDL bindings retain them in YALisp’s lightweight document wrapper.

event

Normalized intent

Keyboard, pointer, text composition, paste, resize, focus, and lifecycle events arrive as stable language data rather than raw browser or SDL event objects.

02 / Application root

Start one application.
Select one binding.

A proposed DOM-level bootstrap helper creates one full-screen application root surface, wires its lifecycle and input flow, and selects the correct underlying binding. A browser environment would create the root through the native DOM. An SDL or bare-metal environment would initialize YALisp’s lightweight in-memory document tree and wrapper, creating an SDL surface when presentation requires one.

dom.application-root.create

Illustrative name only

This provisional name demonstrates the intended single entry point. It is not an implemented function or a settled part of the YALisp API.

browser

Forward to native DOM

The binding would attach the application root to the browser document and forward DOM operations and events to native browser facilities.

sdl

Initialize the lightweight tree

The binding would own the portable document wrapper, connect SDL input and lifecycle events, and create the root SDL surface when needed.

To be defined later: the helper’s final name and arguments, its return value, surface and window options, ownership and shutdown rules, and whether additional roots are supported.

03 / Documents and commands

An IDE is a document
with a language inside it.

dom.documents

document.open · document.create · document.read · document.apply-edits · document.save · document.close · document.watch

Edits are ordered ranges plus replacement text against a document version. A stale edit becomes a structured conflict instead of silently overwriting another author.

dom.selection

selection.get · selection.set · cursor.get · reveal-range

Selections are byte- and line-aware ranges in a document. This gives evaluation-at-cursor and refactoring a portable target.

dom.commands

command.register · command.invoke · command.enable · command.dispose

Commands have stable identifiers, titles, keybinding hints, and availability predicates. Menus and command palettes are adapter presentation choices.

dom.workspace

workspace.roots · workspace.configuration · workspace.find · workspace.apply-edit

Workspace operations are capability-scoped so an extension can edit an approved project without receiving the whole machine filesystem.

04 / Rendering

Retained meaning,
adapter-owned pixels.

The DOM contract carries an accessible retained description, not browser-native node handles. Browser builds forward it into the native DOM; SDL and bare-metal builds keep the lightweight tree in memory and render it through SDL.

01

Begin a frame

surface.begin-frame provides the current viewport, pixel scale, color scheme, motion preference, and a frame token. A renderer never assumes a fixed display size.

02

Submit a tree

surface.present accepts groups, text runs, paths, images, controls, and semantic labels. Stable keys let either adapter preserve focus and incrementally update output.

03

Describe accessibly

Interactive nodes carry role, name, value, state, and action metadata alongside their visual form. Accessibility belongs to the portable contract, not one renderer.

04

Release the frame

surface.end-frame lets an adapter commit, throttle, or discard work while honoring refresh and reduced-motion policy.

05 / Input and lifecycle

Intent arrives as
typed data.

dom.events

subscribe · unsubscribe · event.next · event.prevent-default

Event kinds include key, text, pointer, wheel, paste, resize, focus, and visibility. Text composition remains distinct from key presses.

dom.clipboard

clipboard.read-text · clipboard.write-text

Clipboard access is permissioned and user-gesture-aware. An adapter may return permission-denied or defer until a permitted interaction.

dom.notifications

notify.info · notify.warning · notify.error · progress.open · progress.update · progress.close

Programs communicate intent and diagnostics; the adapter chooses native nodes, an SDL overlay, spoken announcement, or log presentation.

dom.lifecycle

activate · deactivate · suspend · resume · shutdown-requested

Long-running tools release subscriptions and flush document state through lifecycle hooks. Shutdown is a request, not permission to abandon unsaved work.

06 / Extension safety

Power is granted
in visible pieces.

The IDE’s AI assistant, evaluators, and extensions use the same capabilities as ordinary programs. An assistant may propose a document edit, but the DOM adapter shows its scope and applies it through the normal versioned-edit path.

read

Inspect only

Allows document and workspace queries; no changes, network access, or command execution.

edit

Propose and apply

Allows versioned edits only inside approved documents or workspace roots, with conflicts surfaced to the user.

execute

Evaluate intentionally

Allows explicit evaluator sessions with a declared System Interface profile; it does not silently inherit ambient platform authority.

This is the normative YALisp DOM contract and planned binding model. Existing Lispish sources are research evidence, not a runtime implementation or the YALisp specification.
