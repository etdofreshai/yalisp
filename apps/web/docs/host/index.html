Reference interfaces / 03

Host

Rendering and
interaction.

The Host Interface connects a YALisp program to a person-facing runtime: documents, rendering surfaces, input, commands, and accessibility. It is deliberately separate from portable system services.

A Host implementation can be a browser editor, a desktop application, a terminal, or an embedded device. It chooses presentation details; YALisp defines the data and lifecycle exchanged across the boundary.

01 / Boundary

Programs describe.
Hosts present.

YALisp code should not need DOM nodes, GPU contexts, or operating-system event objects. It declares document changes, display content, commands, and subscriptions; the host owns layout, scheduling, focus, and native integration.

document

Persistent editable state

Named text, structured data, selections, and versioned edits. The host decides whether the backing store is a file, database, browser workspace, or collaborative session.

surface

A render destination

An opaque target with size, scale, color capability, and a frame lifecycle. A canvas, terminal viewport, print page, and native window can all satisfy it.

event

Normalized intent

Keyboard, pointer, text composition, paste, resize, focus, and lifecycle events arrive as stable language data—not raw browser or platform events.

02 / Documents and commands

An IDE is a host
with a language inside it.

host.documents

document.open · document.create · document.read · document.apply-edits · document.save · document.close · document.watch

Edits are ordered ranges plus replacement text against a document version. A stale edit becomes a structured conflict instead of silently overwriting another author.

host.selection

selection.get · selection.set · cursor.get · reveal-range

Selections are byte- and line-aware ranges in a document. This gives evaluation-at-cursor and refactoring a portable target.

host.commands

command.register · command.invoke · command.enable · command.dispose

Commands have stable identifiers, titles, keybinding hints, and availability predicates. Menus and command palettes are host presentation choices.

host.workspace

workspace.roots · workspace.configuration · workspace.find · workspace.apply-edit

Workspace operations are capability-scoped so an extension can edit an approved project without receiving the whole machine filesystem.

03 / Rendering

Retained meaning,
host-owned pixels.

The first Host contract uses an accessible scene description rather than a browser-only graphics API. A host may render it through DOM, Canvas, WebGPU, a native UI toolkit, or text-mode cells.

01

Begin a frame

surface.begin-frame provides the current viewport, pixel scale, color scheme, motion preference, and a frame token. A renderer never assumes a fixed display size.

02

Submit a scene

surface.present accepts groups, text runs, paths, images, controls, and semantic labels. The scene has stable keys so hosts can preserve focus and incrementally update output.

03

Describe accessibly

Interactive nodes carry role, name, value, state, and action metadata alongside their visual form. Accessibility is part of the scene contract, not an afterthought for a particular renderer.

04

Release the frame

surface.end-frame lets a host commit, throttle, or discard work. The host controls the actual refresh schedule and can honor reduced-motion preferences.

04 / Input and lifecycle

Intent arrives as
typed data.

host.events

subscribe · unsubscribe · event.next · event.prevent-default

Event kinds include key, text, pointer, wheel, paste, resize, focus, and visibility. Text composition remains distinct from key presses.

host.clipboard

clipboard.read-text · clipboard.write-text

Clipboard access is permissioned and user-gesture-aware. Hosts may return permission-denied or defer until a permitted interaction.

host.notifications

notify.info · notify.warning · notify.error · progress.open · progress.update · progress.close

Programs communicate intent and diagnostics; the host chooses toast, status bar, modal, spoken announcement, or log presentation.

host.lifecycle

activate · deactivate · suspend · resume · shutdown-requested

Long-running tools release subscriptions and flush document state through lifecycle hooks. Shutdown is a request, not permission to abandon unsaved work.

05 / Extension safety

Power is granted
in visible pieces.

The IDE’s AI assistant, evaluators, and extensions use the same capabilities as ordinary programs. An assistant may propose a document edit, but the host shows its scope and applies it through the normal versioned-edit path.

read

Inspect only

Allows document and workspace queries; no changes, network access, or command execution.

edit

Propose and apply

Allows versioned edits only inside approved documents or workspace roots, with conflicts surfaced to the user.

execute

Evaluate intentionally

Allows explicit evaluator sessions with a declared System Interface profile; it does not silently inherit host authority.

This is the normative YALisp Host contract. Existing Lispish sources are research evidence, not the YALisp specification.
